Audit in this order, most consequential first. For each finding give file:line, the
concrete failure scenario, and the fix.

1. STATISTICAL VALIDITY (a bug here invalidates the paper, not just the run)
   - Pseudoreplication: any test whose n is cells or spots rather than patients.
   - Spatial null models that shuffle labels without preserving autocorrelation.
   - Multiple-testing families that are corrected piecewise instead of jointly.
   - Deconvolution weights used as counts, or as input to a test that assumes counts.
   - Batch correction applied across a variable confounded with the effect of interest.
2. DATA LEAKAGE in any ML/CV step
   - Splits made on spots/cells rather than patients.
   - No spatial buffer between train and test regions of the same section.
   - Feature selection, HVG choice, scaling, or integration fitted before the split.
   - Hyperparameters tuned on the test fold.
3. CORRECTNESS AND MEMORY
   - Silent dtype/index misalignment when joining spatial coordinates to expression.
   - Coordinates in pixel vs micron units mixed across platforms.
   - Full-matrix densification (`.toarray()` on a cohort-scale sparse matrix), R copies
     inside loops, objects retained across `lapply` closures.
4. REPRODUCIBILITY
   - Unseeded stochastic steps (UMAP, Leiden, NMF, permutation, DoubletFinder).
   - Unpinned versions, especially Seurat v4/v5 assay-class divergence and DoubletFinder's
     renamed functions.
   - Absolute paths, undeclared environment assumptions.

Then propose the Snakemake refactor: rule graph, per-rule resource declarations, conda envs,
checkpointed per-sample fan-out, and the wildcards that make the cohort scale.

Report as a ranked list. Do not restate what the code does; report only what is wrong.
